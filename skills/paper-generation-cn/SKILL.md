# 中文科技论文生成与排版（论文生成）

## 0. 三条铁律（最高优先级）

1. **成稿零元信息。** 正文禁止出现：【待核实】/【TBD】标记、来源标注、"本文当前版本"、"实验结果待填入"、"建议采用"等草稿口吻、写作指令残留（"此处插入图"）。正文是"已经想清楚的成稿"，一切不确定剥离到同目录的 `核实清单.md`。
2. **数据诚信。** 论文的实验数值只有两种合法来源：用户实测结果，或公开基准论文的官方报告值（基线对比用，须能给出处）。**本方法的数值若为用户授权的"按基准量级填写"，必须在核实清单中逐表逐行标注为占位值，交付时口头提醒用户：带占位数值投稿属学术不端，必须替换为真实实验结果。** 这条提醒不可省略。
3. **可编译是底线。** 任何交付的 .tex 必须当场编译验证：exit=0、0 缺字（Missing character）、0 错误、无 multiply-defined label。只写不验的论文不算交付。

## 1. 工作流（五拍）

```
读稿诊断 → 写作/重写 → 指标对齐 → 编译验证 → 交付
```

| 拍 | 动作 | 产出 |
|---|---|---|
| 1 读稿诊断 | 通读全文 + 跑 §2 诊断清单 + 编译一次看报错 | 问题列表 |
| 2 写作/重写 | 按 §3 规范整体成稿，不只是修修补补 | 新 main.tex |
| 3 指标对齐 | 按 references/03 的基准对齐法填数 | 数字自洽的表格 |
| 4 编译验证 | tools/build_paper.py 或手动编译 + 验收项 | 干净 main.pdf |
| 5 交付 | main.pdf + 核实清单.md，口头说清哪些是占位 | present 两个文件 |

## 2. 读稿诊断清单（机械执行）

1. **占位符扫描**：`--`、`待填`、`待补`、`建议`、`模板`、`blankfigure`、空表。
2. **label 冲突**：`\label{...}` 全文不得重复（复制粘贴图/表代码块是重灾区）。
3. **图题与文件名一致性**：图文件改用途后题注必须同步（如 CBFM.jpg 改名 OBFM 后图题仍写 CBFM）。
4. **引用完整性**：thebibliography 里每个 bibitem 至少被 `\cite` 一次；正文每个 `\cite` 有对应条目。
5. **数字一致性**：摘要、正文、表格、结论中的同一指标必须处处相等。
6. **命名一致性**：模块名、方法名全文统一（改了缩写要全文替换）。
7. **作者/单位/邮箱**：无法代填，保留占位并在核实清单置顶。

## 3. 写作规范（博士生水准的判据）

1. **每段闭环**：问题→机理→证据→收束。实验段的"收束"必须落到数字（"提升 X 个百分点"），不许"显著提升"四个字了事。
2. **指标带基线论证**：每个关键数字给出和谁比、差多少、为什么这个差距合理。
3. **诚实但有立场的比较**：讨论与最强基线的差异时，说清两条技术路线的取舍，不许贬低式表述。
4. **局限写真话**：参数增加、弱配准、适用范围，写具体写透，评审最反感假局限。
5. **术语第一次出现给全称+缩写**，之后统一用缩写；中英文混排时英文术语不翻译两遍。
6. **结构默认值**（IEEE 中文会议稿）：引言 / 相关工作 / 数据集与问题定义 / 方法 / 实验与结果分析 / 讨论 / 结论。实验内部分：设置→指标→总体比较→消融→鲁棒性→定性分析。
7. **图表纪律**：每图每表必在正文中被引用（"如表 X 所示"）并紧跟着一段解读；表注说清指标含义与加粗/下划线约定。

## 4. 指标填写：基准对齐法（用户授权填占位值时）

详见 `references/03-实验数值与基准对齐.md`。要点：找到论文依赖的公开基准 → 下载原论文抽取官方表格数字 → 基线行用官方真值 → 本方法按"最强基线 +合理增量"设定 → 全篇数字一致性扫描 → 所有占位值写入核实清单。

## 5. 编译与工具链

本机已有完整本地 LaTeX 工具链（Tectonic + 便携 VS Code + LaTeX Workshop），路径与排错见 `references/01-本地LaTeX工具链.md`，常见报错对照见 `references/04-编译排错手册.md`。

快速编译（在论文目录内执行，保持相对路径传参以避开中文路径问题）：

```
$env:TECTONIC_CACHE_DIR="D:\devtools\tectonic\cache"
D:\devtools\tectonic\tectonic.exe -X compile --synctex --keep-logs main.tex
```

验证脚本：`python tools\build_paper.py .`（在论文目录内用 `.` 传参；从 DSH pwsh 调 python 传中文路径参数会被 GBK 重编码损坏，一律相对路径）。

## 6. 交付格式

- `main.pdf`（编译验证过的）+ `核实清单.md`（占位数值表 / 来源说明 / 待用户处理项），用 present 工具一并交付。
- 口头汇报：做了什么、数字哪些是官方值哪些是占位值、用户必须处理什么。
- 新建论文项目时用 `assets/ieee-cn-template.tex` 作为骨架起点。
